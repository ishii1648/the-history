# base 勢力データの歴史的帰属 横断監査（TASK-103 / spike）

`data/europe_<year>.geojson` の全勢力を「名称・宗主・存続期間」の観点で史実と
突き合わせ、乖離を一覧化して是正方針を決めるための調査記録。**是正の実装は本
ドキュメントの範囲外**で、確定した対象は個別タスクとして起票する。

- 監査スクリプト: `scripts/audit-attribution.ts`（`deno task audit-attribution`
  で再実行）
- 回帰テスト: `scripts/audit-attribution_test.ts`
- 生成レポート: `.outputs/claude/task-103/attribution-audit.{json,md}`（git
  管理外）
- 対象データ: `data/europe_<year>.geojson` × **20
  年代**（900〜1914、`data/index.json` の `years`）。出典は
  [aourednik/historical-basemaps](https://github.com/aourednik/historical-basemaps)
  @ `62d8f1a03a71f2d3ff17f2d166f7553f256bce68`（GPL-3.0、生成は
  `scripts/build-data.ts`）
- 既存の上書き機構: `data/name-overrides.json` の `renames`（表記ゆれ 7 件）/
  `propertyFixes`（年代付きの properties 上書き 3 件・TASK-102）/ `suzerains`
  （宗主補正 1 件・decision-19）

> 前提の訂正: 起票時の TASK-103 と
> `.outputs/claude/base-territory-accuracy-survey.md` は対象を「全 26
> 年代」と書いているが、実際のスナップショットは `src/config.ts` の
> `SNAPSHOT_YEARS` = 20 年代（900 / 1000 / 1100 / 1200 / 1279 / 1300 / 1400 /
> 1492 / 1500 / 1530 / 1600 / 1650 / 1700 / 1715 / 1783 / 1800 / 1815 / 1880 /
> 1900 / 1914）である。本監査は 20 年代すべてを対象にしている。

## 1. 方法

### 1.1 機械抽出（6 検出器）

`scripts/audit-attribution.ts` が全年代の properties を突き合わせ、乖離候補を
機械的に列挙する。判定（史実として正しいか）は行わず、候補の抽出までを担う。
NAME を持たない
feature（上流がどの勢力にも帰属させていない土地。known-limitations の
`base-unattributed-areas`）は対象外。SUBJECTO の空文字と自己参照は
どちらも「独立」として同一視する（build-data.ts の正規化と同じ扱い）。

| 検出器                  | 内容                                                          | 件数 |
| ----------------------- | ------------------------------------------------------------- | ---: |
| A `suzerainShifts`      | 同一 NAME の SUBJECTO が年代間で変わる                        |   29 |
| B `singleYearNames`     | 1 年代にしか現れない NAME                                     |  108 |
| C `presenceGaps`        | 出現 → 不在 → 再出現（存続期間の途切れ）                      |   23 |
| D `danglingSuzerains`   | SUBJECTO が同年代の NAME に存在しない（宙に浮いた宗主）       |   22 |
| E `shapeCarriedRenames` | 隣接年代で bbox が一致するのに NAME が違う                    |   16 |
| F `colorKeyDrift`       | 同一 NAME の色キー（`powers.ts colorKeyFor`）が年代間で変わる |   29 |

F は A と**同じ 29 件**になった。NAME が同じなら色キーの揺れは SUBJECTO 由来
しかないためで、「改名によって色キーが変わる」ケースは F では拾えず E でしか
検出できない（例: 1279 `Serbia` → 1300 `Raška` は別キー = 別色）。

### 1.2 史実照合と確度

抽出された候補を年号付きの史実と突き合わせ、次の 3 段階で確度を付ける。

- **A（明確な誤り）**: 年号を伴う定説と矛盾し、解釈の幅では説明できない
- **B（解釈の余地あり）**: 名目上の宗主権・同君連合・移行期など、どちらの表記も
  一理あるが年代間で一貫していない
- **C（妥当）**: 一見不自然だが史実として説明でき、対応不要

### 1.3 この監査で拾えないもの（網羅性の限界）

- **ポリゴンの形状**: 境界線の位置・面積の誤りは対象外。境界そのものの粗さは
  known-limitations の `borders-are-approximate` に既述。形状の誤りが疑われる
  例は §5 に列挙するにとどめる。
- **1 年代のみに現れる誤り**（検出器 B の 108 件）:
  全件の史実照合は行っておらず、 主要勢力と既知候補に絞って確認した。B
  は「消滅・出現の妥当性を人が確認する ための一覧」として扱う。
- **欧州域外**: `EUROPE_BBOX`（西経 25°〜東経 60°、北緯 34°〜72°）でクリップ
  された断片（中央アジア・アラビア半島の一部など）は帰属の妥当性を検証していない。
- **年代の粒度**: スナップショットは最短 21 年（1279→1300）、最長 100 年超の
  間隔がある。「その年ちょうどの帰属」で判定するため、10 年程度のずれは確度 B
  として扱っている。

## 4. 単独で判断が要る 2 件（名称の上書き）

`propertyFixes` は properties の上書きしかできず、**ポリゴンを消す・分ける・
形を変えることはできない**（decision-14 / decision-18: 出典をたどれない形状を
史実データに混ぜない）。そのため「存在しない勢力が描かれている」「実体より
はるかに広い範囲が一勢力の名で塗られている」は、次の 2 択になる。

| 対象                         | 案 (a) NAME を上書き                                                                       | 案 (b) known-limitations に明記して現状維持                         |
| ---------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| A-5: 1400 `Seljuk Caliphate` | `Anatolian beyliks`（アナトリア諸侯国）へ。1308 年に滅んだ勢力名が地図に残るのを避けられる | 「1400 年のアナトリア中央部は滅亡済みの勢力名で塗られている」と明記 |
| B-7: 1279 / 1300 `Ryazan`    | `Other Rus Principalities` へ（1200 年に同名の前例あり）                                   | 「ルーシ諸公国は代表名で一括して塗られている」と明記                |

**推奨は (a) + (b) の併用**。理由:

- 表示される勢力名は `data/name-ja.json`（decision-6）が担うが、日本語表記は
  英語 NAME をキーにするため、誤った NAME をそのままにすると誤った日本語名が
  出続ける（実測: `Seljuk Caliphate` → 「セルジューク朝」、`Ryazan` →
  「リャザン」）。
- NAME の上書きは形状を触らないため decision-14 / 18 に抵触しない。一方で
  「どの名前にするか」は編集判断なので、根拠（1308 年の滅亡・1200 年の前例）を
  `propertyFixes` の `note` に必ず残し、形状が実体と一致しないことは
  known-limitations で補う。
- ただし NAME の上書きは既存 `propertyFixes` に前例が無く（現行 3 件は
  `SUBJECTO` / `PARTOF` / `BORDERPRECISION` のみ）、色キー（`colors.json` の
  再生成）と `name-ja.json` の追加を伴う。**採否は起票時に人が決める**。

### 4.1 判断の結果（TASK-106: 2 件とも (a) + (b) を採用）

TASK-106 で 2 件とも **(a) NAME 上書き + (b) known-limitations 明記**
を採用した。 判断の根拠・上書き先の選び方・波及の実測は decision-23
に記録している。実装は `data/name-overrides.json` の `propertyFixes` 2
エントリ（`Seljuk Caliphate` 1400 / `Ryazan` 1279・1300）で、回帰テストは
`scripts/base-properties_test.ts` の `EXPECTED_NAME_OVERRIDES`。

| 対象                         | 上書き後                   | 上書き先を選んだ根拠                                                                                                                                                                        |
| ---------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A-5: 1400 `Seljuk Caliphate` | `Anatolian beyliks`        | 上流自身が同じ 1400 年に `Beylik of Aydin` を独立勢力として収録しており、総称 NAME（`Cuman Khanates` / `Celtic kingdoms` / `Other Rus Principalities` / `Baltic Tribes`）も上流の語彙にある |
| B-7: 1279 / 1300 `Ryazan`    | `Other Rus Principalities` | 上流自身が 1200 年に同種の広がりへ使っている NAME。1492（約 15.0 万 km²）・1500（約 2.0 万 km²）には実体どおりの `Ryazan` が別に存在し、131 万 km² と同色・同一勢力に見えるのを断てる       |

実測した波及（`data/colors.json` の再生成）:

- `Ryazan` の上書きは色の入れ替えを **起こさない**。複合キー
  （`Ryazan|Mongol Empire` → `Other Rus Principalities|Mongol Empire`、
  `Ryazan|Khanate of the Golden Horde` → 同様）の色は宗主名から導かれ、
  ベース名の集合が変わらないため色は同一の値を保つ。
- `Seljuk Caliphate` の上書きはベース名を 1 つ増やすため、決定的プロービング
  （decision-5）の玉突きで **無関係な 15 勢力の色が入れ替わる**（Norway /
  Novgorod / Netherlands / Kalmar Union など）。これは TASK-71 / TASK-86 /
  TASK-96 と同じ性質で、新しい勢力名が増えるたびに起きる既知の副作用。
- 差分は計 `+3 キー / -2 キー / 15 色入れ替え`。`name-ja.json` は
  `Anatolian beyliks`（「アナトリア諸侯国（ベイリク）」）の 1 件追加のみ
  （`Other Rus Principalities` は 1200 年の分で既出）。

`renames` との適用順は問題にならない。`build-data.ts` は
`applyNameOverrides`（renames）→ `applyPropertyFixes` → 封土切り出し →
`normalizeSubjectProps` の順で当てるため、`propertyFixes` の `name` は
リネーム後の名前で指定でき、上書き後の `NAME` はもう `renames` を通らない。
ただし **`NAME` だけを変えると、自己参照だった `SUBJECTO` / `PARTOF` が
上書き前の名前を指したまま残り、宙に浮いた宗主と分裂した色キーを作る**
（`Anatolian beyliks|Seljuk Caliphate` のような複合キーになる）。上書きは `NAME`
と自己参照側を同時に行う。

実装時（TASK-105）に本表から変えた点:

- `base-nominal-suzerainty` の例からノヴゴロドの貢納を外した。§2 A-3 として
  TASK-104 が 1279 / 1400 を独立へ是正済みで、現行データには残っていない。
  恒久的な例として残るのはアルジェ・チュニス摂政領（§3 B-5「対応しない」）で、
  ハノーファーは §3 B-4 = TASK-107 の対象なので勢力名は挙げず「同君連合が従属
  として収録されている箇所もある」という一般的な書き方にとどめた。
- `base-shape-reuse` は実測で 1279 `Serbia` / 1300 `Raška` / 1400 `Bosnia` の 3
  年代が bbox だけでなく座標まで完全一致する（同一の 28 頂点・約 84,306 km²）
  ことを確認した。1279 の `Serbia` は名称として妥当なので、`years` は誤りが
  目に見える 1300〜1400 のままにしている。
- `Mecklenburg-Strelitz` の位置ずれは 1800 年だけでなく **1783 年も同一形状**
  （bbox (6.71, 51.66)-(11.18, 53.90)）で、1815 年の `Hanover` の外形とほぼ
  重なる（名前と形の対応の入れ替わりとみられる）。`years` は連続する範囲を 1
  つしか持てず、1300〜1800 に広げると 1492〜1715 の 9 年代に誤った「この年代に
  該当」バッジが出るため、`years` は広げず本文で 1783 / 1800 に言及する形に
  した（UI は制限を常に全件表示し、`years` はバッジの有無だけを制御する）。
